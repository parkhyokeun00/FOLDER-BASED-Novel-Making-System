# Board Freshness Audit

Run this after chapter close and before starting the next chapter.

Its job is to prevent the manuscript from racing ahead of the system boards.

## Freshness check

Confirm that the latest chapter's effects are reflected in:

- chapter map
- affected object states
- active threads
- traction
- reader state
- timeline
- source references when the chapter materially used outside material

## STALE rule

If a board should have changed but did not:

- mark it `STALE`
- update it now, or
- record a temporary waiver with a reason

## Progression rule

Do not begin the next chapter while a critical board remains stale without an explicit waiver.
