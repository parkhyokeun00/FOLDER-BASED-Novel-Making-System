# Complexity Budget

This system is allowed to grow only as fast as the story actually needs.

## Purpose

Prevent design enthusiasm from turning the workspace into a system that is harder to run than the novel is to write.

## Scale budgets

### Shortform

Required:

- objects
- scenes
- arcs
- one timeline
- one simple reader board if needed

Avoid unless clearly justified:

- full weave board
- advanced checkpoint rhythm
- too many dashboards

### Long-form

Required:

- objects
- scenes
- arcs
- threads
- timeline
- architecture
- reader memory
- traction

Use selectively:

- subtext registry
- pulse layer
- misreading design

### Ultra-long-form

Full stack allowed:

- reader
- pulse
- subtext
- traction
- resonance
- weave
- checkpoints
- dashboards
- firewall and audit protocols

## Justification questions before adding a new board

1. What exact failure does this board prevent?
2. Can an existing board already do that?
3. Is this needed now, or only later?
4. Who updates it and at what cadence?
5. What happens if it goes stale?

If those answers are weak, do not add the board.

## Rule

No new permanent board without a clear failure it prevents.
